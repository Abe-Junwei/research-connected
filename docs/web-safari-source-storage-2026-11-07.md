# Safari 来源复核保存超限

用户报告：`来源更新未保存，继续使用原项目：The quota has been exceeded.`

## 定位

提示由 `src/source-revalidation.ts` 的保存失败分支产生。正式网页原来调用预览工具的 `commitWebRevalidation`，先把完整项目写入 `research-connected-web-settings-before-source-review`，再替换当前设置。额外的整份副本可能先耗尽 localStorage；即使直接替换原值仍可成功，复核也被挡住。保存失败后来源复核时间无法写入，刷新又会重试。

复现用实际旧保存函数和容量受限存储：当前设置与新设置均可单独容纳，复制备份则抛出与 Safari 报告相同的 `QuotaExceededError`。这是本地存储保存路径，和每天成功操作次数不是同一额度。未读取用户 Safari 的项目内容或实际占用；具体剩余空间、存储权限仍取决于用户浏览器环境。

## 修复

- 正式 Web 复用现有 `writeWebProjectSettings`，只原子替换当前值，不再额外复制全部项目。预览工具和插件的保存行为保持原样。
- 真正空间不足时保留当前项目，提示中文恢复说明；当前标签页暂停自动来源复核最多 24 小时，避免每次刷新都重复请求和提示。成功项目保存或显式清理后允许再次复核。
- 暂停期间导出仍标记来源复核未完成，不能把旧数据说成已核对。
- 已有历史来源备份保留；空间不足且存在该备份时，在提示及 info 中提供明确的清理按钮，只删除历史来源备份键。保留当前项目，随后重新加载重试。当前标签页有未结束任务时阻止该操作。

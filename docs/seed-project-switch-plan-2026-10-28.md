# “设为种子”改为切换项目：行为方案

日期：2026-10-28。状态：产品语义已由用户确认；本文是实施方案，未改生产行为。

本次确认取代《整体改进方案》第 7、11.4 节及《实施路线图》S31–S32 中“在同一项目更换单一起点并撤销”的约定。后续多种子功能另行设计；不从本入口推导“同项目增加起点”。

## 1. 操作合同

- 在项目 A 的论文节点选择“设为种子”，意思是打开以该具体文献版本为种子的项目 B。A 的种子、名称、图谱和项目内状态不被改写。全库阅读进度仍按既有共享规则显示。
- 若目标只有一个匹配的已存项目，打开其已存图谱和视图，不暗中重新采样。若有多个匹配项目，列出项目供选择，不能按存储 key 或最近修改时间猜。若无匹配项目，构建并保存新项目；名称默认取目标题名。
- 匹配先按目标版本标识判断，不把同研究的另一版本或相似节点当成同一项目。切换到当前项目的当前种子是无操作。项目列表显式选择仍按项目 key 打开。
- 只切换发起操作的主面板。另一面板若停留在 A，继续显示 A；若已打开 B，则接收 B 的共享图谱更新，但保留自己的缩放、筛选、选择和侧栏状态。嵌入继续使用代码块指定的种子图。
- 构建完成并保存成功之前，A 仍是当前项目且图谱可见。失败保留 A 的输入框、项目名、图谱、详情、视图和保存状态，并给出可重试错误。旧请求晚到不覆盖后来选定的项目。
- 成功后一次性更新当前面板的项目名、种子输入、种子摘要、图谱、详情、筛选与年份范围、统计、导出范围、保存状态及研究脉络。旧叙事结果不带到 B。打开已有 B 使用 B 的视图；新建 B 使用默认视图。
- “撤销图谱编辑”不负责跨项目返回。通过项目列表返回 A；A 的已存视图和状态仍在。首版无需另加“返回上一项目”入口。

## 2. 当前实现与改动范围

节点菜单在 `src/app.ts` 先将目标写入输入框，再调用带 `swapProjectKey` 的 `buildResolved`；这会把新图存到 A 的 key，复用 A 的名称、保留来源和状态，并建立同项目起点撤销点。普通输入构建已有“找已存项目或建新项目”的分支，但同种子多项目、具体版本和界面提交时机仍需统一。`src/view.ts` 的保存接口可按新项目种子创建 key；已有 `matchingSeedProjects` 与项目列表可供选择，不另建项目注册表。

实施顺序：

1. 将节点菜单与输入构建接到同一个“解析目标 → 选择已有项目或创建”的入口；移除节点菜单的同项目 `swapProjectKey` 路径。明确具体版本的匹配规则及多项目选择。
2. 将创建结果先保存到目标项目，再切换发起面板；保存失败或请求失效不修改 A，也不留下半创建项目。项目切换调用同一个完整呈现流程，避免项目事件处理只更新部分字段。
3. 移除仅服务于“同项目换种子”的撤销检查点和 UI 语义；保留正常图编辑撤销。更新原 S31/S32、浏览器检查及最终组合验收，不以旧断言“项目 key 不变”判成功。

## 3. 最小验收

| 情境 | 必须观察到的结果 |
| --- | --- |
| A 中目标没有项目 | 创建 B；B 名称取目标题名，项目 key 与 A 不同；A 的快照、名称、排除、暂存、手动和深挖来源逐项不变；返回 A 可恢复 |
| 目标已有唯一项目 B | 打开 B 的快照和视图；不新建、不把 A 的状态写进 B、不无故联网重建 |
| 目标有两个项目，或同研究有另一版本项目 | 两个项目可明确选择；另一版本不被误选；取消后停留 A 且无写入 |
| 请求失败、保存失败、撤稿准入未通过 | A 的项目名、输入、图、详情、年份、保存提示保持一致；可重试；没有半成品 B |
| 连续点两个目标、两个主面板并存 | 最后一次有效选择生效；旧响应不覆盖；只切换操作所在面板，另一面板原项目不跳转 |
| 成功切换后刷新或重启 | B 的项目名、种子元数据、图、统计、详情和导出属于 B；A 仍可从项目列表打开；全库阅读仍共享，项目内状态隔离 |

验收同时检查主面板窄宽度与键盘节点菜单；生产 CSS 下观察实际界面。先在固定离线样本跑反例，再用真实 Obsidian 双面板和重启验证。现有测试通过只说明旧行为能运行，不证明此合同已实现。

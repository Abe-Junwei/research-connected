## 目标与边界

用户希望能在单种子文献图中辨认基础作品。应将四件事分别判断：文献是否进入候选和图谱；经典候选是否命中；节点大小表达什么；星芒能否被看见。高被引不是经典认证，光芒弱也不能证明未命中。

首批解决**解释和可见性**：固定可复现基线，评估累计被引尺寸，补强经典星芒并展示命中依据；并行厘清引用证据的缺失状态。随后再用真实标注样本评价召回、排序、经典阈值及布局。前一批不以新模型、外部服务、修改采样策略或多种子为前置条件。

当前已实现：经典候选至少满八年、非种子且非撤稿，满足本地不同引用者 ≥2、累计被引 ≥1,000、或满足当前成熟样本前 10% 且 ≥100 的任一通道；无八篇截断。详见[当前判定](../src/aggregates.ts)。这是已采用的经验规则，不在视觉首批中改动。

## A1/A4：节点尺寸

### 建议的产品语义

- **建议默认方向：代表版本的累计被引数决定普通节点大小。** 年均被引保留为详情中的辅助信息，不称最近一年增长率；若年份未知则年均不可用。不同版本不累加，遵守现有代表版本/准入规则；引用数来自数据源，不称学术质量。种子保留单独的最小尺寸，明确它是交互例外。
- 经典候选资格与尺寸独立：不让所有经典自动变大、不用星芒代替数量，也不调整用户已有的经典阈值。时间筛选只隐藏/显示论文，说明大小表示**当前**累计被引，不是历史时点的引用。
- 尺寸大小是图内近似视觉比较，不宣称半径或面积与引用数量成比例；详情显示原始被引值，图例注明数据源与种子例外。平方根或对数压缩、上限截断如采用均应明确，不暗示可按面积求倍数。

### 先比较，再选参数

在完全相同的图数据下，报告至少三条候选，所有对数使用 `log1p`，相同节点采用相同可用引用值：

1. **现行基线**：年均引用、图内最小/最大值与平方根映射；保留现有 4–14 CSS 像素和种子 ≥11 像素。
2. **累计引用 + 常规压缩**：以 `log1p(累计被引)` 映射到同一尺寸范围，归一范围取图中非种子的真实最小/最大值，种子仍套用同一尺度及 11 像素下限；仅种子时仍保留种子下限。
3. **累计引用 + 稳健上界**：与候选 2 一致；至少 20 个有可用引用数的非种子节点时，使用最近秩 95 分位作为上界，高于上界者饱和；少于 20 个则用真实最大值。阈值、分位点只是**实验设定**，不是行业标准。大量相同值时报告并列和饱和数量，不允许宣传被截断的节点仍有严格大小排序。

候选 2/3 的全零、全部相同非零、无可用数值应各有确定输出；先在 A1 列出结果，保留当前同值/全零行为作为比较，不在本计划伪称已经通过。图例与详情需标明原始值，且不得用种子最低尺寸推断其引用更多。若方案 3 造成太多节点同尺寸或小样本不稳定，选择方案 2 或重新设计；没有实验结果前不锁定生产公式。

同一固定样本逐篇输出：ID、年份、被引、旧/新指标、旧/新半径、排名及经典命中；比较含/不含极值的尺寸变动、被压到上限的数量，列出老高引与新文献大小顺序。用户给的三本分别核对真实数据；若未在当前图中，报告无法计算并说明原因。截图覆盖主面板和嵌入的深/浅色、三种布局、正常和小图/密集图、缩放及筛选。

### 未知值与旧数据

[OpenAlex 转换](../src/openalex.ts)当前把缺失被引数转换为 0，[PaperRecord](../src/types.ts)只存数字，旧快照无法区分原始零与缺失。不得把已有 0 批量判成已确认零，也不得推断缺失年份的真实年龄。A1 报告已知的证据边界；A4 若要真正区分新旧记录，需要先设计源字段可用性在网络数据、版本代表、快照保存/恢复、合并/拆分及显示中的流转和兼容规则。旧快照的零如果没有来源证据，显示为“历史记录：无法确认零或缺失”；不自动联网重写旧项目，也不把版本被引数相加。此处需要单独确定现有格式兼容和迁移/回退，不在本方案假定已解决。若此依赖未闭合，A4 可以先完成旧数值尺寸比较及明确说明，不能声称已完整解决未知被引。

### 验收

- 固定样本中：较高可用累计被引的非种子不得小于较低者；有截断时允许同尺寸但需说明。1991/3,500 与 2023/400 的前者不小于后者；相同引用数、不同年份尺寸相同。
- 零、缺失、负数/非有限输入、全部相同、仅种子、代表版本切换及极值样本得到确定结果，无 `NaN`；未知与真实零只有在来源可区分时才区分，旧数据不被伪造为已知。
- 同一图的年份/内容过滤不会悄悄重标度；新增/移除节点重算时记录尺寸变化。主面板、嵌入的首次加载、保存重开、深挖、投影/筛选、主题切换和三种布局一致；不破坏缩放、碰撞、命中与标签避让。
- 不因为此项改旧数据、扩大版本合并、重新计算经典身份或额外请求 API；不因通过浏览器截图就称真实 Obsidian 验收完成。

## A2：经典星芒与解释

- **判定共用**：节点、图例数量和详情使用同一份现有经典证据；详情列出实际命中的本地引用者数、累计被引或样本前 10% 通道，以及成熟年限。仅列当前可证明的事实；未知年份、撤稿、种子不冒称命中。图例统计范围与画布实际节点/过滤范围需明确，一旦选择范围，所有入口使用一致规则。
- **视觉方向**：暗色经典节点至少有四个方向的可辨认星芒，尺寸以 CSS 像素为单位设置下限，影响强度只加长或增加细节。初始试验线宽 1–1.2 CSS px、从节点边缘向外 5–7 CSS px；这是待视觉验证的起点而非已确定参数。保留数据色、种子/选中环和现有节点命中范围，减少动态效果下静态可辨认。
- **防误读与遮挡**：星芒和种子/选中态分开；焦点淡化、动画最低点、密集重叠时检查是否还能识别，不能只在透明画布量非零像素。必要时调整绘制顺序并检验不会覆盖其他节点、文字或关系方向。浅色主题单独检验当前光晕，是否加同类标记根据结果决定。
- **验收矩阵**：真实背景下半径 4/5/14、低/高经典影响、不同语义颜色、缩放 0.3/1/2、普通/选中/淡化、动画最低点/减少动态效果、稀疏/密集、DPR 1/2；每个入口至少覆盖主要边界。比较经典与非经典邻点截图，并检查节点点选、图例数量和详情证据；保留现有 Canvas 像素断言和性能回归。再检查真实 Obsidian，不能以本机一次同步耗时代替全设备性能结论。

## A3：结构相似证据的缺失

[当前实现](../src/similarity.ts)只要任意上下文非空就可返回结构相似 0；即使 A/B 的参考列表缺失、上下文只有 C/D 也会这样。先修正**解释与可用状态**，不顺带改入选、加权和布局：

- 对共享参考与共被引分别记录“有可比较数据 / 证据不足”；计算结论注明来源和采样范围。两端都有可用参考列表，零共享仅代表当前获得的列表中零共享；一个列表为空或缺失且无法证明完整时不能推断全局无共享。共同被引只描述本次采到的施引上下文，A/B 不出现不能解释为全库不共被引。
- 数值/未知状态及各分量和来源在节点详情、主面板、嵌入、保存恢复、身份投影和重算路径保持一致；缺失来源、外部回填只覆盖图内子集、部分请求失败均需标明限制。为避免暗中改变排名，保留现有内部权重，评测后再讨论是否重新归一；显示分不能把不可比较伪装成完整的 0。
- 最小反例：A/B 缺参考且上下文仅 C/D → 未知；A/B 均有已取得的列表但没有交集 → 当前列表零共享；样本上下文分别包含 A、B 但无共同出现 → 当前样本内零共引，不代表全库零；直接引用存在但结构不可比 → 仍保留引用方向和来源；S2/Crossref 局部补全与真正完整列表不得混同。旧快照缺可用性信息时显示未知/来源不足，不补造。

## B1：经典、召回与排序评测

先建立独立标注集：跨领域、年代、书籍/论文和引用覆盖；每篇标注相关/不相关/证据不足、基础候选/非基础/不确定及理由，记录分歧。用户提供的三本是正例线索，但不据此宣布所有高引作品均为经典。固定当前算法、数据时间和请求预算，分别评估：

1. **候选获取**：人工标注的相关或基础作品是否进入候选池；记录来源、样本页数、成功/失败与截断。未取到与已取到未入选分开。
2. **候选选择**：固定同一个候选池，比较当前排序与候选方案的前 N 精确率、已标注相关/基础作品召回、分领域和新旧作品差异。MMR λ=0.7 的合成 sweep 不是现实效果证明；不先把权重或配额当成已校准。
3. **经典资格**：记录规则命中通道、逐项误标/漏标、覆盖缺失和版本影响；对近期高引、低引基础、综述、未知年份、撤稿、种子、重复引用及超过八个合格项做反例。优先完善解释，再决定要不要改八年/1,000/相对百分位，不靠单个图调阈值。
4. **成本与稳定性**：每种方案同时记录新增请求数、延迟、字段缺失及来源；同一预算比较采样，同一候选池比较排序，报告标注样本规模及不确定性。没有可信标注或数据不足时保持现行策略，不能宣布召回提升。

摘要与 SPECTER 向量当前在初次选择后补取；未来若要参与候选入选，需先证明覆盖、计费/延迟、失败回退及跨语言效果，并保留原始入选依据。PageRank、额外语义召回、FWCI、新模型、自动版本合并与多种子均不作为本计划首批必做项。

## B2：布局与组合验收

固定数据及随机/迭代条件，测节点轻微增删、缺边、不同采样对分组与位置的变化；报告群组变化、邻近关系变化、遮挡和耗时，不把布局距离解释成经过验证的语义距离。不预先替换布局或聚类算法。

全部实施切片应与既有单种子、版本归属、筛选、阅读状态、项目保存、撤稿、恢复及导出合同联测。整体发布仍遵守既有路线图和真实宿主门槛：数据快照/回退、浏览器主面板与嵌入、真实 Obsidian、网络失败/截断、窄容器和键盘可达性各有证据。视觉改动和计算改动可分别交付，不以报告或测试样本冒充已发布功能。

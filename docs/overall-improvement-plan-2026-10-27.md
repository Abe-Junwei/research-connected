## 1. 总体取舍

先让用户操作可达、状态不会悄悄分叉、关系证据可信，再增加入口和推荐。保留当前插件的模块化单体结构和共用画布；在现有算法上落实已确认的研究级聚合、去重和版本评分规则；不安排框架迁移、微服务、全量重写或新的通用状态管理框架。

主工作流保持“发现论文 → 判断关系 → 暂存/排除 → 阅读与文献笔记 → 导出”。主面板承担完整探索，嵌入承担阅读中的轻量查看。同名操作共享业务规则；允许不同布局和入口。

四条完成标准：

1. 同一操作在主面板、嵌入及恢复后产生一致的持久化结果。
2. 相似、直接引用、共被引、耦合及推荐候选有清楚边界，来源不能由合并数据反推。
3. 窄容器、键盘、不同主题下，核心动作可发现、可完成、有反馈。
4. 新功能保留现有项目身份、阅读、暂存和排除；迁移失败可恢复。

## 4. 已确认的状态归属与迁移（包 B）

本轮 grilling 已完成共同理解确认。以下是产品合同，不再把阅读状态归属列为待决策。具体字段、存储形状及接口实现仍需检查代码后设计，本文不把合同视为已实现。

- 阅读进度全库共享；已确认属于同一研究的不同版本也共享。暂存、排除、手动保留及深挖保留属于项目。
- 同一论文跨项目旧进度不一致：保留所有原值及来源，集中由用户确认；一致数据自动迁移。未确认时显示“阅读进度待确认”，继续允许浏览与其他操作；用户直接选择进度也可解决该项冲突。
- 初次确认不同版本属于同一研究时取最高进度，覆盖其中已有的跨项目/笔记旧进度冲突，原值备份。此规则只用于版本合并，不能作为日常更新规则。
- 合并后用户明确修改进度，包括从已读改回阅读中，按最新明确意图同步。以后合入带不同旧进度的新版本，不覆盖这个明确修改，而列入待处理。
- 笔记也是编辑入口，有效状态修改更新所有项目及所有参与同步的匹配笔记。多份笔记全部同步，但不合并笔记正文。并发修改或同步失败后又手动修改，保留两边值并暂停覆盖该笔记，等待确认。
- 删除阅读字段表示该笔记退出阅读同步，不改变共享进度；无效值保留原文并提示，修正前暂停该笔记同步。不能把删除、无效值或失败遗留旧值识别为“未读”新意图。
- 共享进度保存成功而部分笔记写失败：保留已提交进度，显示部分同步失败，保存失败记录，不尝试把全库进度退回。恢复可写或重新打开时有限自动重试，也支持手动重试；每次写前核对没有新的手动修改，持续失败不循环重试。
- 版本归属冲突、阅读冲突、同步失败及排除范围待确认统一进入“待处理”入口，按论文显示原值、来源、数量及动作。仅当前操作无法继续时要求当场选择。

迁移顺序：固定代码与数据基线 → 完整备份 → 审计旧身份归属与旧操作范围 → 生成冲突清单 → 自动迁移一致数据并保留待确认项 → 写入版本号并重读验证 → 切换读取入口。迁移可重跑，不重复创建项目或笔记，不改变旧项目 key。

迁移前置与旧数据解释：

- 当前 work-identity 可按同 DOI 或完整书目信息匹配聚合，项目加载还会归并聚合节点状态；这不等于可信跨版本关系。先区分同版本重复记录、已确认版本关系、旧启发式聚合和人工分开决定。不同 DOI 且无可信关系/人工确认的旧聚合不得直接成为共享研究，也不得触发“初次版本合并最高进度”。保留原始记录和状态，待确认后再按合同处理。
- 旧聚合节点上的暂存/排除只有代表节点状态时，不能可靠反推出具体版本或整项研究意图。可追溯的操作按原范围保留；无法还原的进入范围确认，保留原值和来源，不静默升级为覆盖未来版本的整项规则，也不静默丢弃旧排除。未确认范围内的显示与操作须明确提示，不能伪装成已确定规则。
- 本次迁移必须覆盖纯 v2、纯旧格式及混合项目，不能只在存在 v1 快照时触发保护。已有 data-before-work-identity-v2.json 不是本次迁移前备份的替代；新备份须对应本次完整原始数据，不覆盖历史备份。
- 重跑与重启检查从上次实际落盘输出开始，不能反复喂同一份旧输入冒充幂等。分别在保存新数据、版本标记、重读验证和切换读取入口前后注入失败，证明可恢复、冲突保留、旧操作不会重复应用。

首版仅保证单设备及其多个面板一致，不支持跨设备并发修改；跨设备冲突检测另行交付。降级必须先恢复迁移前完整备份，再使用旧插件；明确说明迁移后的新操作不会自动带回旧版，不维护双格式同步。

验收必须区分共享数据保存失败与笔记同步失败：前者不得假报提交成功，后者按上述部分失败规则保留已提交结果。现有 commitPaperReading 只是待核实实现，不能沿用与本合同相反的全量回滚语义。

测试切换归包 B 所有：保留共享保存失败不得假报成功的检查；将“笔记失败必须全量回滚”的旧断言替换为共享提交保留、部分失败记录及安全重试断言，并覆盖多笔记部分成功、重启恢复、字段删除/无效及重试前手改。包 A 可固定旧行为复现，但不得将旧断言通过记为新合同验收；新旧存储与提交入口须成套切换，不能只修改测试掩盖语义缺口。

| 展示 | 容器布局、画布标签、筛选、焦点、面板、菜单 | 不自行决定持久化顺序或证据归属 |

调整顺序：包 B 先确定身份、状态、项目 key 与迁移边界；独立的“查看论文”和证据终态可先收拢，阅读提交由 B 统一所有权。随后落实版本筛选与导出范围、项目级图谱请求/提交、成员保留来源和一次撤销。只提取已经有两个真实调用方且规则相同的部分，保留主面板和嵌入自己的布局组织。

版本筛选不能简单复用当前 nodeVisible：当前种子无条件可见，导出函数还会重新执行 workIndex。实现时明确区分参与计算的合格版本集合、仅供展示的起点例外、用户选择的导出版本集合。边与统计只用合格版本；导出消费已确定的版本及归属，不再次自动聚合来改变用户范围。“每研究一个版本/全部未排除版本”和“包含起点例外”分别显式选择，复用同版本字段，不拼接虚构条目。

项目会话与撤销必须逐步实现，不能留到最终组合验收才发现缺失：

1. 项目 key 与当前起点解耦，明确嵌入的一次项目选择和持久关联，禁止按相同种子猜归属。
2. 项目级请求失效与完整图谱提交：多个主面板共享图谱而各自保留缩放、筛选、选择和面板状态；旧请求不得覆盖新提交。现有单挂载 graph-session 及局部锁不等于项目级一致性，不要求为此另建通用状态框架。
3. 按自动采样、手动加入及深挖批次合成成员来源；重建与撤销均应用最新状态及保留来源，撤回只移除指定来源。
4. 将现有挂载内图编辑检查点替换为项目共用的一次起点/采样图撤销。不得恢复旧 paperStates 覆盖新阅读、暂存、排除，也不得复活已撤回来源；起点已排除先处理冲突。两面板行为检查通过后再接用户入口。

证据合并必须满足：同一事实重复加入不重复计数；来源并集不创造来源；合并顺序不改变结论；显示聚合后仍可追溯原始记录。旧快照缺少来源时显示未知/待重新获取，不伪造确认。缓存区分成功有数据、成功无数据、临时失败；用户重试不能无限读回同一个异常值。

视图 key 和网络缓存 key 分开：网络 key 包含影响取数的设置，视图 key 包含影响展示的配置；失效必须可解释。#1 origin 变更按 issue 丢弃保存视图，同时保留项目身份和用户状态。

## 6. UI/UX 收敛与验收（包 D）

本轮不提出换品牌、重做视觉风格或删除背景效果。先修“操作看不见/点不到/点了没变化”，再调整层级、对比和密度。

- 400px 左右窄容器打开详情时，详情暂时占满当前容器，保留“返回图谱”和关闭入口；返回恢复原缩放与选择。

浏览器自动化用生产 CSS 和真实指针交互；截图证明外观，断言证明动作结果，两者缺一不可。再在真实 Obsidian 中补主面板、Reading view、Live Preview、多窗格、笔记重命名、主题切换及键盘任务。浏览器预览不能替代宿主验收。

## 11. Grilling 已确认的完整首版合同

本节补齐例外与操作边界，与第 4 节共同构成用户确认的合同。来源为本轮逐题回答及最终共同理解确认；与早先建议不同处，以确认后的规则为准。推荐反馈和多起点评分中涉及的规则是后续功能约束，不要求首版实现推荐请求或多种子入口。

### 11.1 研究身份、版本与证据

- 不同 DOI 的预印本和正式版，只有可信数据源明确标注版本关系，或用户手动确认，才归入同一研究；标题/作者相似只提示。版本归属全库统一，影响全部项目和嵌入。
- 手动合并/必须分开的决定持续优先；数据源相反证据只提示，用户可撤销手动决定恢复自动判断。
- 数据源关系单次缺失不自动拆分：保留关联及原证据，标为待核查。可信来源明确冲突时冻结现状：未合并的仍分开，已合并的暂保留，等待确认。明确否定关系进入核查/拆分流程，不能仅凭接口缺失等同否定。
- 拆分时各项继承当前共享进度；保留合并前记录供手动恢复，不要求逐条分配合并后的阅读修改。
- 图谱聚合为研究节点，仍保存各版本原始标识、字段和引用证据。节点标题/年份/作者来自同一版本；普通节点优先符合筛选且未排除的正式发表版，其次最新预印本，无法判断时稳定排序；标明展示版本。起点节点例外，显示实际选中的起点版本。
- 直接引用按研究间关系去重，不因版本或服务重复而加粗；详情列出版本、方向、年份及服务来源。双向引用保留两个方向，不推断因果。版本内自引用不在主图画自环，也不计研究间强度，详情保留事实。
- 共被引、耦合及相关计数按已确认研究归属去重：引用预印本与正式版可视为引用同项研究，但必须能追溯版本，不能让版本数量放大分数。
- 归属变化立即用已有数据重算打开项目的聚合、边和统计，尽量保留视角/选择，不自动联网或重采样；资料不足明确标记。

### 11.2 项目排除、暂存与推荐反馈

- 单版本排除只影响所选版本，其他项目和同研究其他版本不自动排除。聚合节点只以未排除版本贡献可见关系和排序。
- 聚合节点“排除”先选择版本，另有明确“排除整项研究”操作。整项排除覆盖目前及未来发现的版本，直到恢复规则改变。
- 从整项排除中恢复一篇，保留整项规则，为该版本建立恢复例外，其他及未来版本仍排除。
- 研究拆分：两项都继承整项排除，各版本恢复例外随版本保留。研究合并：不静默把一项原有的整项排除扩大到另一项；旧排除继续生效，新合入原有版本继续显示，扩大范围须确认。未确认期间，新版本能明确归于合并前某项则沿原规则，否则不放主图，进入“排除范围待确认”。
- 暂存只针对所选版本，清单保留版本；推荐提交时同研究正例去重。普通跨版本暂存/排除同时存在时，该研究反馈不提交，等待选择倾向。
- 特例：从整项排除中明确恢复并暂存的版本，作为正例优先；整项规则仍隐藏其他版本及未来版本。再次排除此版本后正例优先失效。不能把普通暂存一概当作排除覆盖指令。

### 11.3 视图筛选与现有导出

- 年份/语言/类型等筛选以版本为单位；节点、边、统计和当前视图导出只使用符合条件且未排除的版本。详情可额外展开筛掉的版本。
- 起点不符合视图筛选时保留为明确标注的例外；其引用边不计筛选结果，当前视图导出默认不含这个例外，用户明确勾选才包含。不得与项目排除或撤稿准入混为一谈。
- 启用排除撤稿只过滤明确撤稿版本；同研究其余版本可留，但显示研究级警告，不能将“无撤稿标记”等同“确认安全”。
- 保存起点后来被标记撤稿：暂停重新建图，保留上次图并醒目标警告；由用户更换起点或明确允许该起点例外，不静默换版本。
- BibTeX/YAML/Markdown 导出提供“每项研究选一个版本”与“全部未排除版本”的明确范围选择；对当前视图导出还须满足当前筛选。不把多个版本字段拼成虚构条目。
- 打开/创建笔记按具体版本选择；该版本多份笔记再选文件；创建针对选定版本，不自动合并正文。

### 11.4 单一起点、请求与一次撤销

- 首版仍只有一个起点；聚合节点先选具体版本，再在同项目更换起点并重建，项目 key 不变，保留阅读/暂存/排除、手动保留及未排除深挖成果，清除旧视图位置。
- 当前起点不可直接排除；先切换到可用版本，或后续多起点时撤下该起点；没有替代不能排除，说明原因。
- 以最新起点选择为准，尽可能取消旧请求，其余旧结果不应用；期间仍可操作用户状态。只有最新完整结果替换原图，失败保留原图，首次失败显示未完成。
- 一次撤销项目共用，任一主面板可触发；恢复上一组起点与采样图，不联网，保留最新阅读/暂存/排除及保留来源。仅当前运行期间保留，重启失效，不能连续追溯更早历史。
- 上一图起点已经被排除时暂停撤销，由用户选择恢复该版本后撤销或取消；不静默改排除。
- 对后续 #1：同研究最多一个 origin，切换版本重建；每个 origin 指定具体版本。候选按每个 origin 对其未排除版本的最高分，再跨 origin 取最低分，即允许不同版本分别连接不同起点，详情展示贡献版本。
- 后续多起点中任一 origin 请求失败，保留原图，不忽略失败起点或当零分；成功但候选资料不足时，不进入正式排序，另列资料不足并支持补全，不编造分数。

### 11.5 主面板、嵌入与图谱成员

- 同项目主面板共享起点、图谱、深挖、版本归属和新增证据；缩放、筛选、选择及面板展开各自独立。旧请求不得覆盖新状态。
- 嵌入保持代码块自己的单种子图，不跟随项目起点和深挖；阅读全库共享，暂存/排除只在明确关联项目时适用。
- 未关联嵌入执行暂存/排除，先选已有项目，没有则可创建，不按相同种子猜测归属。选择仅本次操作有效，不自动建立关联；持久关联必须明确选择“将此嵌入关联到项目”。
- 嵌入关联项目已排除其种子时，暂停建图；可明确恢复该版本、解除关联或改代码块种子，原排除不静默改变。
- 列表“查看论文”打开详情，不自动加入；主动“加入当前图”才持久保留，暂无已知关系可成为孤立节点，标明手动加入，不伪造边、不自动暂存、不自动作推荐正例。
- 手动加入及深挖保留跨起点重建仍带回，除非排除。采样上限只约束自动采样，起点和明确保留可使总数超出，说明原因及数量，不自动丢弃用户选择。
- “取消手动保留”只移除这一来源，不产生负反馈；节点仍来自采样/深挖时继续存在并说明原因，彻底隐藏走排除。
- “撤回这批深挖结果”只移除该批保留来源；其他批次、手动保留或恢复图的自动采样仍可使节点存在，不改阅读/暂存。
- 撤销及重建应用最新保留来源，不复活已撤回批次/已取消手动保留；旧图自动采样本身选中的节点仍可出现。

## 12. 首版组合验收与分期收束

本轮用户已确认：以下必须组合通过才发布首版。内部可以分工作包及小提交，但不能以先发布 bug 修复替代这次约定的完整首版交付。

| 场景 | 必须证明的结果 |
| --- | --- |
| 迁移两次、重启、备份恢复 | 幂等、项目 key 不变、一致数据自动迁移、冲突不丢；降级须恢复备份且明确新增操作不随之回退兼容 |
| 纯 v2 / 旧格式 / 混合格式 + 已有旧备份 | 均在本次完整备份保护下迁移；不跳过纯 v2，不复用或覆盖早期备份；重启读取首次实际保存结果 |
| 迁移写入及切换入口中断 | 在保存数据、版本标记、重读验证与读取切换前后分别失败；重跑不重复应用旧操作、不丢冲突，失败可恢复到明确状态 |
| 旧启发式聚合 + 不同 DOI + 无可信版本证据 | 不把旧聚合自动认作已确认研究，不触发最高进度；原记录、原状态及人工分开决定可追溯 |
| 旧代表节点/别名上的暂存与排除 | 范围可追溯则保留；不可还原则待确认，不升级为覆盖未来版本的整项规则，不丢弃原操作；暂存/排除冲突可解释 |
| 跨项目旧冲突 + 初次版本合并 | 初次版本合并最高进度优先、原值备份；未合并普通冲突仍人工确认 |
| 合并后明确降进度 + 新版本合入 | 明确修改不被旧高进度覆盖；进入待处理；拆分双方继承当前进度 |
| 多笔记、部分失败、手动修改、重试 | 共享提交保留；未修改文件有限重试；新修改冲突不覆盖；字段删除退出同步、无效值暂停 |
| 共享保存失败与笔记失败分离 | 共享保存失败不假报成功；共享保存成功而部分笔记失败不回退，失败记录重启可恢复；旧全量回滚断言不再作为新合同标准 |
| 手动归属与接口缺失/冲突 | 人工决定不被推翻；缺失不拆分、冲突冻结；无网络本地重算可追溯证据 |
| 研究合并/拆分 + 整项排除/恢复例外 | 拆分继承规则及例外；合并扩大前确认；不明新版本进入待处理；反馈优先级按第 11.2 节 |
| 版本聚合 + 筛选 + 撤稿 + 导出 | 同版本字段、研究去重、双向边及自引用正确；起点筛选例外和撤稿准入分别处理；导出不混字段 |
| 起点不符合筛选 + 两种版本导出范围 | 起点仅作明确展示例外，其边不计筛选结果；导出默认不含例外，显式包含才加入；每研究一个版本/全部版本不被导出时重新聚合改变 |
| 两主面板 + 起点重建 + 状态修改 + 撤销 | 最新请求生效；图谱共享/视角独立；撤销无网络、不倒退用户状态或复活保留来源；排除起点冲突人工选择 |
| 两面板不同视角 + 旧请求晚到 + 撤回来源 | 图谱提交不带入另一面板视图；重建及撤销后旧响应失效；检查点之后的新进度/暂存/排除保留，撤回批次及取消手动保留不复活 |
| 独立嵌入 + 项目选择/持久关联 | 一次操作不建立关联；关联才应用项目规则；排除种子暂停建图，恢复/解除/改种子均明确 |
| 图外查看 + 手动加入 + 深挖撤回 + 节点上限 | 查看不修改成员；加入可孤立；保留跨重建；按来源撤回不造负反馈，不静默丢节点 |
| UI矩阵 + 键盘 + 真 Obsidian | 默认完整图；主动选择才淡化；窄详情可返回恢复视角；所有关键动作可达、有反馈，生产CSS缺失不能通过 |

后续 #1–#4 按功能开工前再细化；已确认的 origin 版本、评分、推荐反馈及项目边界持续约束后续方案。#5–#9 保持原有独立待办。首版不包含跨设备并发冲突检测、Zotero/Canvas/完整多种子/推荐接口实施。本次访谈与文档确认不构成生产代码开工或发布授权。

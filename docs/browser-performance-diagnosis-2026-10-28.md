# 浏览器卡顿排查（2026-10-28）

## 已复现并修复

在用户保存的 W1532553368 图（50 节点、113 关系）上测量浏览器同步事件处理和 requestAnimationFrame；DPR=2。测试操作为布局按钮、连续平移以及现有浏览器回归中的 300 节点/483 关系合成图。以下为本机观测，不是所有设备的帧率保证。

1. **高频交互重复绘制**：[画布](../src/map-canvas.ts)的 pointermove、缩放、物理微调、星芒循环分别整图重画。300 节点回归中，每帧连续派发 5 个拖动事件，共 12 帧/60 个事件，旧实现产生 72 次绘制，约 278 ms；新增断言实际失败。共享 requestDraw 后，连续更新合并为一次绘制，12 次/约 192 ms。保留星芒运动、渐变、标签和交互，销毁时取消待绘制帧。公开的离散状态更新仍可立即绘制。
2. **无变化的年份筛选触发关系重算**：布局按钮的 syncScrub 在非时间布局下发出 null。[主面板](../src/app.ts)和[嵌入](../src/embed-mount.ts)即使当前已经是全部年份，也重做版本关系投影。仅修绘制与布局浪费后，放射切换仍约 465 ms，证明还有此独立瓶颈。现在相同 cutoff 直接返回，真正修改年份仍走原投影流程。
3. **计算后丢弃的布局**：adoptGraph 在 reflow=false、全部节点已有坐标但没有 nearId 时，也运行 placeLayout，最后用 old.x/old.y 丢弃其结果。现在只在明确重排，或没有停放锚点且存在新节点时计算布局。尺寸和来源状态仍重算；新增节点、显式重排保留原逻辑。

## 尚存边界

多标签页竞争和不同设备/GPU/真实 Obsidian 尚无受控对照证据；没有把它们认定为已证实原因。未关闭用户其他页面，未改经典判定和节点尺寸公式。

最终检查：完整 npm test、生产构建及浏览器回归通过；新增的无效筛选/丢弃布局/重复绘制三项断言均通过。最终浏览器回归 12 帧/60 个事件为 12 次绘制，约 192.6 ms；300 节点单次绘制中位数 3.8 ms、P95 4.0 ms。测试期间切换页面会暂停 rAF，曾使缩放等待超时；恢复前台重跑完整回归通过，未放宽原断言。

## 节点选择与右侧详情的第二轮排查

实际 50 节点、113 条关系项目中，通过 Shift+方向键触发与指针选择共用的 `map.onSelect → showDetail` 路径，三次同步回调耗时分别为 390.7、455.1、414.7 ms。详情原先为查找一个展示版本，每次调用完整 `projectVersionGraph`，连带重建引用投影和派生评分。

将已有版本选择规则提取为 `projectVersionNode`，整图投影与详情共用；详情只读取所选节点的版本，不再重建整图。保留种子例外、筛选、排除与待确认版本规则；从当前图节点取版本记录，避免调用者传入的旧对象遗漏版本。没有引入缓存失效机制。

更新预览后，在同一实际项目的暗色视图连续选择三次，同步回调分别为 10.1、7.5、10.0 ms，实际 DOM 标题正常更新。此为选择回调耗时，未包含输入排队、浏览器绘制、异步摘要请求和延迟保存，不代表完整点击到呈现延迟。

新增回归检查：单节点选择与整图投影的展示字段一致，语言筛选无匹配返回空，排除版本后选择一致。完整 npm test、生产构建、预览构建、主面板与嵌入浏览器回归通过。外部摘要补全仍可能受接口 CORS/网络失败影响；未在本轮更改接口或整图重算算法。

## 拖动、缩放与悬停的第三轮排查

50 节点实际项目的前台平移采样（30 帧）中，pointermove 同步处理为 0–0.3 ms，帧间隔通常 16.6–16.7 ms；本次没有复现该图持续平移掉帧，不能把用户感到的全部拖动延迟都解释为绘制过慢。

确认并修复以下问题：

- 缩放与力学动画先在 rAF 更新状态，再另约 rAF 绘制，多等一帧。改为同一个帧回调更新缩放／力学后绘制，星芒沿用这个循环。新增“第一帧绘制缩放值必须等于当前视图值”回归：旧实现实际失败，新实现通过。以 60 Hz 计去除约一帧的额外等待；这不是对完整输入到屏幕延迟的测量。
- 切换布局清零旧力学热度，避免节点回弹继续扰动年份／放射布局。
- 悬停同一节点不再重复改写标题、读取 tooltip 宽高；内容变化或画布 resize 后重新测量。回归断言连续两次移动仅读取一组宽高。
- 完全离开视口的节点不再创建星芒渐变和执行绘制，保留 radius + 32 px 边界，避免裁断可见光晕；标签与连线仍按原规则处理。回归覆盖完全在外与光晕仍在边缘的两种情况。
- 年份轴先读取页面位置，再写时间条样式，避免同帧写样式后立即读取布局。
- 先验／衍生列表的 shownNodes 与详情一样，改用共用的单节点版本选择，不再只为取得可见 ID 重算整图；自动保存后的列表刷新也复用此路径。

300 节点、483 条边回归中，60 次拖动事件／12 帧仍为 12 次绘制，约 182 ms；单帧绘制仍为数毫秒，没有声称渲染器整体数倍加速。新增检查与原有连续动画、星芒外观、标签避让、快速缩放、主面板和嵌入交互一并验证。

未增加 Worker、标签缓存或降低星芒效果；50 节点实测中标签测量累计约 0.6 ms／32 帧，不足以支持增加缓存复杂度。真实大图重新布局和版本关系投影仍同步执行，完整输入到屏幕延迟与真实 Obsidian 宿主尚未测量。

最终检查：完整 npm test、生产／预览构建与浏览器回归通过。最终 300 节点采样单帧绘制中位数 3.9 ms、P95 4.3 ms，帧间隔中位数 16.7 ms、P95 17.7 ms；12 帧拖动为 12 次绘制、约 187.1 ms。新增同帧缩放、布局切换停止力学、tooltip 测量复用和视口边界检查全部通过。

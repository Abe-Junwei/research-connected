# Research Connected 实施路线图：最小可验收切片

日期：2026-10-28。依据：[整体改进方案（10-28 修订）](./overall-improvement-plan-2026-10-27.md)，特别是第 4、11、12 节。本文只编排实施依赖，不重定义产品合同，不代表生产代码已实施或授权发布。

## 1. 使用方式与边界

- 按下表依赖实施；编号是推荐顺序，不代表所有任务必须串行。每片对应一个可独立审查的行为结果，通常一个小提交/PR；若失败原因、回退或验收无法独立说明，继续拆，不按文件数量机械拆分。
- 首版范围是 A/B/C/D 及第 11 节首版合同；内部可合入小片，但第 12 节组合验收通过前不发布半套新规则。完整多种子、推荐请求、Canvas、Zotero 和 P2 功能不进入首版。
- 先复用现有模块、测试和宿主事件；不预建通用状态框架、迁移平台或推荐框架。表中模块是查找入口，不是新增文件清单，实际修改前须追踪全部调用方。
- 所有切片初始状态均为“待实施/待复核”。已有修补先补证据，反例已通过就关闭该片，不重写已有代码。测试全绿不等于合同完成。
- 新身份、状态和迁移逻辑先在测试样本中实现，不提前接入真实 `loadSettings` 或写回旧数据。生产入口在 S39 集成；开发验收用固定样本，不维护长期双格式同步。S25–S34 的请求、提交和撤销只对照样本项目 key。`app.ts` 与 `embed-mount.ts` 里现有的 `researchProjects[seed.id]` 读写留到 S39 才换成新 key。
- 项目级请求失效和共用撤销放在 `project-state` 一侧。`graph-session` 只保留单次挂载的选择、年份和侧栏，不扩成项目事件总线。
- 同设备多面板一致是首版要求；跨设备并发检测不在本路线。内部切片不改变原项目 key，也不借机建立新工作树或重建所有项目。

## 4. 并行范围、回退与每片交付记录

### 可并行与不能并行的边界

- S02–S06 与 S07 起的领域准备可并行；S35–S38 的旧入口修复可提前做，新增入口必须在集成后再验。
- 身份/状态规则的存储形状与迁移解释由 B 统一所有权；C 不另建阅读状态或项目归属来源。共享文件存在冲突时串行合入，不让多个切片同时重写提交路径。
- S21 起的图谱投影可与 S19/S20 的迁移样本演练并行。S33 无需等待换起点 UI。只选项目并写暂存时依赖止于 S14；嵌入创建或选择项目会与主面板在途建图抢同一次提交时才加 S25。
- 主面板多 origin 顶栏属于后续功能，不因 D 中原方案提及长标题而提前实现；首版只验单起点长题名及现有操作。

### 回退点

| 时间点 | 回退方式 | 不能做的事 |
| --- | --- | --- |
| S39 前，尚未切换真实数据 | 停用未接入的新逻辑，保留旧运行行为；开发数据副本可丢弃重建 | 把测试样本成功当作用户数据已安全迁移 |
| S39 验收库迁移失败 | 停止新写入，保留失败记录，恢复本次完整备份并验证，或按已验证步骤重跑 | 半迁移状态下用旧插件继续写，或只恢复代码不恢复数据 |
| 新格式产生用户操作后需降级 | 按整体方案恢复迁移前完整备份；明确迁移后操作不会自动带回旧版 | 承诺无损自动降级、长期双格式同步，或假定笔记和插件数据跨文件原子提交 |

每片记录统一使用整体方案第 10 节模板，至少包含：片号、合同/A/U 编号、基线、触达调用方、最小反例及结果、落盘/重启证据（适用时）、未覆盖项、回退点。使用现有测试组织，不为每片新建一套框架。脱敏样本不包含 API 密钥、原始敏感笔记或可复用凭证。

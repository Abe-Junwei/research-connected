# 核心算法审查与产品对标

日期：2026-10-28。范围：检查当前工作区源码、现有验证与用户的网页预览状态；查阅其他产品的一手公开资料。没有修改生产代码，也没有做同种子、同数据、同时间的竞品实测。此文描述当前源码；此前[经典文献调研](./classic-paper-algorithm-research-2026-10-28.md)前半部分记录的是改进前的历史状态，其末尾另有后续实现说明，不能把前半部分当作当前行为。

## 总结与优先级

最需要改进的是**候选召回、信号缺失的表达、经典标记的可辨识性及评测证据**，而不是先增加复杂模型。当前已有分渠道采样、文本/主题相似、引用结构、去重、MMR 和局部引用支持；这些是实用启发式，不是经过领域验证的效果保证。文献是否进入候选、是否被选为节点、是否满足经典条件、星芒是否看得见，是四个不同环节。

| 优先 | 问题 | 最小改进与验收方向 |
| --- | --- | --- |
| P0 | 小经典节点即使命中，暗色星芒仍细且短；外观无法证明身份 | 保留独立经典资格，给星芒设屏幕像素级最低宽度、长度和亮度，并在详情展示命中理由；做真实背景、缩放和密度下的盲测 |
| P1 | 取样和入选偏向高被引；文本/向量补全发生在入选之后 | 把召回及排序分别评估，保留低引用近期及图中基础文献；先对真实案例测漏召回，再决定补充哪些候选来源 |
| P1 | 引用结构缺失可能被显示为零相似 | 区分不可比较和已比较但为零；分别记录共享参考、共被引样本覆盖与来源 |
| P1 | 经典阈值为图内经验规则，缺领域校准 | 展示本地引用数、总被引、年份、命中通道和数据缺失；用跨领域正反例验证，不称自动认证 |
| P2 | 不同阶段和通道的分数尺度不统一 | 保留已有的入选依据与后算展示分区分；评价不同尺度融合及小样本稳定性 |
| P2 | 聚类与布局依赖被稀疏化的边 | 说明颜色和距离是样本内结构提示，不是领域分类或真实引用距离；用固定样本和扰动测试稳定性 |

## 实际算法与对标

### 1. 候选采样与入选

[loadNeighborhood](../src/neighborhood.ts) 从 OpenAlex 取种子参考文献、施引和 related；默认标准档目标分别为 80/40/20，节点默认上限 50。参考和施引按被引数降序获取，相关作品使用另一通道；请求页数和上限会影响覆盖。每组去重后，先预留 related 约 22%（至少 6 个，受空间及数量限制），剩余节点在参考和施引间分配，再由 [selectNeighbors](../src/neighborhood.ts) 的 MMR 选择，λ=0.7。入选相关度是归一化的被引影响分与本地文本/主题分各半，缺语义时只用影响分。MMR 候选相似度为词项余弦和主题余弦；未知值按零惩罚。

排序发生在详情摘要和 SPECTER2 向量批量补充前；后续语义分和放射布局可使用它们，但不会重新决定初次入选。因此开了向量不等于向量召回或向量重排。入选顺序先 related、后参考、再施引，MMR 对之前已选对象的惩罚会受到这个顺序影响。被引排序与有限页数也可能漏掉近期、低被引或书目数据薄弱的相关作品。具体漏掉哪些须在真实样本核验，不能从规则直接推定召回率。

[ResearchRabbit 官方说明](https://learn.researchrabbit.ai/en/articles/12875619-what-s-behind-researchrabbit-s-search-algorithm) 区分候选生成与排名；[Litmaps 官方说明](https://docs.litmaps.com/en/articles/9029858-search-algorithms-in-litmaps)将引用、共同作者和文本搜索分为可选方式。公开资料不提供足够信息推断其精确融合权重。相比之下，本项目的语义目前主要在已采集的邻域内排序或展示，并非独立文本检索通道。

建议：先让诊断清楚区分“未取到、已采样未入选、入选后被过滤”，并保留采样截断和来源；用已有数据实验扩大有代表性的近期/低引候选、共同基础文献候选，再评估真正的文本召回是否值得额外请求。不要因竞品支持多种子就立即改变目前单种子产品范围。

### 2. 引用相似度、证据与展示边

[buildSimilarity](../src/similarity.ts) 将文献耦合余弦、采样共被引余弦、直接引用按 0.55/0.35/0.10 相加；种子最多保留七条高分边，其他节点各保留至多两条达阈值的候选边，孤点另加弱连线。共被引仅来自采到的施引文献参考列表，并非全库计数。边稀疏化用于展示：存在直接引用不保证相应边一定显示。弱兜底边可以没有引用证据，只应解释为采样邻域中的弱连线。项目已把直接引用、共享参考、共被引分别记录，属于可解释的基础。

具体缺陷：`pairParts` 只要任一上下文参考列表非空，就会将结构相似度视为有覆盖。反例：A、B 都没有参考列表，已取到的上下文只包含 C、D，则 A/B 被显示为结构相似 0，而不是不可比较；零不能证明两者不相关。建议把“参考列表可比较”和“共被引样本足以观察该对”分别记录；对未覆盖返回未知，同时保留原始计数与来源。不要仅把一个零改成另一个未验证的相似分。

[Connected Papers 官方说明](https://www.connectedpapers.com/about) 公开基于共同被引和共享参考，约从 5 万篇中选出几十篇，图是相似关系而非引用树；并未公开足以复现其权重和完整候选流程的细节。[Inciteful 官方方法文档](https://github.com/inciteful-xyz/inciteful-academic-docs/blob/master/paper-disovery-explained.md) 将重要性 PageRank 与相似度分开，使用 Adamic/Adar 的文献耦合和 Salton 共同被引。该文档包含旧数据源信息，不能保证当前线上设置。可在固定数据上比较稀有共享参考的加权是否有效，不能直接宣称任何一种更准，也不应在稀疏绘图边上算 PageRank 后称为等效。

### 3. 语义、影响及经典候选

[text-similarity](../src/text-similarity.ts) 使用 BM25 和 OpenAlex 主题余弦：两者均有时 0.6/0.4；如果种子及节点都有 SPECTER2 向量则使用向量/主题 0.75/0.25，否则回退本地通道。BM25 按当前候选池最大值归一，不同候选池之间的绝对值不可直接比较；向量余弦与 BM25 归一分也未证明同尺度。[neighborhood](../src/neighborhood.ts) 用 0.55 结构 + 0.45 语义形成后算的种子距离分；它不等于入选时的 0.5 权威 + 0.5 本地语义。详情应区分这两种语义和计算时点。有限英文停用词及 CJK bigram 对多语言、形态变化和缺摘要文本可能表现不同，需按领域实测。

[classicNodeIds](../src/aggregates.ts) 当前规则：非种子、非撤稿、年份已知且至少 8 年，同时满足至少两个不同图内引用者，或累计被引至少 1,000，或在至少 10 篇成熟作品的当前样本中进入被引前 10% 且至少 100 引用。不同通道取并集，无八篇截断；`referenceLists` 与直接引用边参与去重计数。仍可能因取样、不同版本、未知年份或低引用领域漏标；也可能把高引用但并非基础的综述标入。种子不自动标经典。此前用户列出的三本高引用书的元数据满足当前累计被引条件，但这只能说明**若当前节点使用相同年份、引用数且未撤稿，则会命中**；本轮未逐个读取页面节点数据及实际分类，不能声称这三本现均已显示星芒。

[OpenAlex 官方引用说明](https://help.openalex.org/data/works/citations/) 提供按领域、年份、类型计算的归一化影响指标，其覆盖与分母取决于数据源；[Semantic Scholar 高影响引用说明](https://webflow.semanticscholar.org/faq/influential-citations)描述的引用上下文模型需要引用文全文。二者都不是学术经典认证，缺失不能视为负证据。优先展示命中通道及其来源、样本范围，而不是把新的阈值包装成普适标准。

### 4. 聚类、尺寸与布局

[detectCommunities](../src/communities.ts) 对非弱连线做确定性加权标签传播，最多 12 轮，按组大小编号；[layout](../src/layout.ts) 以力导向加同组聚拢、碰撞和压紧处理，放射布局距离使用后算种子分，年份布局横轴为发表年。图中邻近、组色和节点大小是样本与布局的产物，不等同学科标签或真实引用树。节点半径从年均被引的图内相对值按平方根映射到 4–14 CSS 像素；影响排名、经典资格和大小各用不同数据及归一方式。

建议解释这些编码；增加固定样本的节点加入/删除、抽样扰动和重排稳定性检查，观察组别变动及距离误读，再决定是否替换聚类或布局。不要为得到类似竞品的视觉而把力导向位置解释为确定的语义距离。

#### 节点尺寸的补充审查

上文只描述了计算方式，未充分评估其风险。当前尺寸以**当前累计被引数 ÷ 发表距今年数**为输入，再对当前整图的最小/最大值做平方根归一，映射到 4–14 CSS 像素半径；种子半径至少 11 像素。这个数是跨发表期的粗略平均，不是最近一年的引用速度，也不是按领域归一的影响力。圆面积不与引用数或年均引用成比例。

- **旧经典可能显得小。** 按 2026 年计算，1991 年发表、被引 3,500 次的文献约为 100 次/年；2023 年发表、被引 400 次的文献约为 133 次/年，后者会更大。[现有测试](../scripts/verify.ts)明确锁定这一行为；其是否符合产品意图需要决定，并不是计算器算错。
- **未知年份被当作只有一年。** [yearNormalizedCitations](../src/visual.ts)对未知年份取 1 年；同一篇被引 1,664 次的作品，若年份是 1992 年约为 49 次/年，年份缺失则变成 1,664 次/年。这会抬高未知年份节点，并可能压缩其他节点。未知并不等于新近。[数据转换](../src/openalex.ts)还把缺失被引数转成 0，现有数据模型无法区分缺失与确实为零。
- **极值与图的构成影响所有尺寸。** 假设图内最低年均为 0、最高为 133，上述两篇半径约为 12.66/14；如果再加入一篇年均 2,000 的文献，两者变为约 6.24/6.58 像素，尽管自身数据未变。图中只有一种非零数值时统一为 9 像素；全零则为 4 像素；种子另有 11 像素下限。节点增加、删除或重建后会重算，普通时间筛选只隐藏节点，不重新计算大小。
- **历史视图不是历史影响回放。** 拖动年份筛选只改变可见性，大小仍使用当前累计被引和当前年份；不能把画面解释成该年当时的引用影响。暗色星核与光晕也会影响视觉上的大小，不能仅凭光晕辨认数值。

建议先明确尺寸语义：若目的是展示累计学术影响，可考虑以累计被引作为默认尺寸，并把年均引用单独展示；若目的是展示跨发表期平均，则保留现有指标但明确名称和局限。无论哪种，未知年份/引用应有明确未知态，归一范围应对极端值进行稳健处理，并注明种子最小尺寸。上述是待评估方案，并非已验证的更优公式；需用旧经典、新高引、未知年份、异常值、全零及节点增删的固定样本比较，检查主面板和嵌入入口、筛选、缩放与时间视图。经典身份和星芒继续作为独立标记，不能直接把节点变大当作经典判断。

#### 节点尺寸：业内与学界方法对标

此前本报告对标了候选和引用相似度，**没有对节点尺寸做充分对标**。下表区分用于决定大小的指标与把指标映射成像素的方式；官方没有披露公式时不推断其参数。

| 对标 | 公开方法及证据 | 与本项目的区别 |
| --- | --- | --- |

| Consensus | 官方[引用图说明](https://help.consensus.app/en/articles/13846077-citation-graph)称节点大小表示被引数，年份与连接度由其他视觉通道表达；未披露尺寸映射公式。 | 将累计引用与其他信号分开，有利于用户直接理解大小含义；高被引仍不代表经典或质量。 |

**选择上的结论**：对于用户当前寻找基础文献的场景，累计被引用作默认尺寸是有业内产品参照的候选方案，而非学术意义上的最优解。它偏向积累时间长的作品；年均有助于观察新近作品，FWCI服务于同类比较，局部引用数描述当前图内关系，这些信号不能互相替代。不存在已核实的通用公式可以同时表达经典地位、速度与领域影响。尺寸若经过截断或非线性压缩，应让用户知道它只用于大致比较，不可从面积直接推断引用比例。

## 小节点星芒：原因与补强方案

[drawNode](../src/map-canvas.ts) 中暗色主题的经典节点始终保留细节，但低影响档 `importance=0` 只画两条轴、线宽 0.6 CSS 像素；若半径 4，最长一轴从中心到端点约 8 像素，较短一轴约 5.2 像素。线性渐变在中心最亮、末端透明，实际露在核心外的清晰部分更短；动画期间整体透明度还会变化，非焦点被淡化时整体乘 0.25。节点坐标随缩放变化，暗色节点半径本身按屏幕像素绘制，所以缩小造成的拥挤和覆盖是主要风险之一，不能简单归因于节点半径随缩放缩小。绘制顺序按半径从小到大，大节点可能覆盖小节点的光芒。浅色主题采用同色光晕，并不绘制相同的衍射星芒。

当前 [verify-review-browser](../scripts/verify-review-browser.ts) 用透明测试画布检查一个半径 5、低档经典在概览下有像素，最大 alpha 至少 20；这证明绘制存在，不证明复杂背景、不同颜色与真实图密度下能辨认。

建议先在暗色主题做一个可验证的最小方案：

1. 每个已命中的经典都维持**固定屏幕尺寸**的最小四向星芒，给线宽、可见长度及静态亮度设下限；影响分只增加额外长度/细节，不决定基本标识是否存在。建议首轮试验线宽 1–1.2 CSS px、从节点边缘向外至少 5–7 CSS px，并以截图和辨识测试调参；这些是试验值，不是已验收参数。
2. 光线用较亮的同色系核心和渐隐外围，避免只加大模糊光晕；保留类别颜色、现有种子优先级和减少动态效果设置。焦点淡化可以保留，但不要让用户误以为该节点未标记，详情另明确显示经典候选及命中证据。
3. 密集图上限制星芒扩展与亮度，验证经典彼此重叠、与种子/选中态区别及视觉遮挡；必要时改绘制顺序，但不得改变命中范围、节点大小和引用语义。浅色主题单独检验同色光晕与背景对比，再决定是否需要相同星芒。
4. 在真实深色图背景中覆盖半径 4/5/14、最低/最高影响、不同节点颜色、缩放 0.3/1/2、普通/选中/淡化、动画最低点与减少动态效果、稀疏/密集及 DPR 1/2。既看实际截图与人工辨认，也测像素差异和遮挡；保留现有功能和性能测试。预览与 Obsidian 实际宿主均需分别验收。

## 可执行评测计划

1. 固定若干不同学科、年份、书籍/论文和引用覆盖程度的单种子图，包括用户的 W1532553368；保存数据快照、时间、来源、失败/截断及版本。对候选总池与最终节点分开人工标注相关/基础/非相关/证据不足，不把被引数当唯一真值。
2. 对每种策略分别报告候选覆盖、已标注基础作品召回、前 N 精确率、误标/漏标及分领域/年份/文献类型结果；记录请求数、延迟、缺失率和用户操作成本。标注者分歧及少样本不确定性单独报告。
3. 在同一固定候选池比较 MMR、字段缺失处理和相似度选项；在同一预算下单独比较候选采样。否则候选量和数据源的变化会与排序效果混淆。
4. 如要与产品效果比较，记录每个产品的实际查询时间、配置、导出范围和不可控数据源差异；产品间排序不是领域金标准，也无法据此反推闭源公式。

现有 [MMR sweep](../scripts/mmr-sweep.ts) 是一个确定性合成邻域，相关性仅按被引量计算；可用于检查参数行为，不能证明 λ=0.7 对真实用户更优。本轮未重跑完整测试、实测第三方产品、验证真实 Obsidian 宿主，也未逐篇核对用户图中经典节点的命中状态。

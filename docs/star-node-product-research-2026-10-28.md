# 暗色星体节点：产品实现调研

日期：2026-10-28。范围：公开的一手资料与当前本地绘制代码；仅调研，未修改生产代码。官方资料能证明的机制与本项目建议分开记录，不能把暗色圆点图直接称为物理星体渲染。

## 结论

适合 Research Connected 的做法是：沿用二维节点与数据颜色，在暗色模式用小亮核、同色窄光晕形成恒星观感；选中环、标签、连线继续独立表达交互和关系。真实天文产品提供星光外观参考，知识图谱产品提供可读性与数据编码参考。无需因这项外观改动更换渲染引擎。

## 产品与公开机制

### Google / Chrome Experiments：100,000 Stars

这是 2012 年的历史实现案例，不能当作当前浏览器性能基准。作者明确介绍：远处恒星使用 THREE.js 粒子系统；近处太阳用红外灰度图查颜色渐变，并用面向相机的平面精灵表现日冕，额外的环面着色器表现耀斑；相近恒星可以复用这些外观方法。它说明远景点与近景细节可以分级，而非为每个远处恒星绘制复杂球体。[作者实现说明](https://web.dev/case-studies/100000stars)

本项目可借鉴：小节点只画亮核与弱光晕，明显放大或选中时才增加细节。不照搬太阳纹理和耀斑：当前论文节点缺少这些视觉属性的研究语义。

### Stellarium：点光源光晕

官方 `StelSkyDrawer` 接口把星等转换为半径与亮度；`drawPointSource` 画点光源光晕，接收 RGB、屏幕可见性检查和闪烁因子。其职责还包括眼睛适应、缩放和星等限制。这是明确公开的星光实现机制，不是根据截图猜测。[官方类文档](https://stellarium.org/doc/24.0/classStelSkyDrawer.html)

本项目可借鉴：把节点实体半径与光晕范围分开，控制亮度上限，避免暗色密集图中所有节点糊成光团。星等与真实天文色温不适用于论文数据，不应引入。

### Cosmograph：数据点形状、图片和焦点环分离

官方支持几何星形等点形状；这是分类符号，并不等于恒星光晕。图片节点由 URL 提供纹理，可独立设置图片尺寸，加载后默认隐藏底层形状。焦点和悬停环是单独配置的交互表达。尺寸映射提供自动 symlog 等策略，度数映射会限制极端值影响。[点形状](https://cosmograph.app/docs-lib/features/point-shapes/)、[点图片](https://cosmograph.app/docs-lib/features/point-images/)、[尺寸](https://cosmograph.app/docs-lib/features/size/)、[焦点环配置](https://next.cosmograph.app/docs/lib/api/internal/interfaces/GraphConfigInterface/)

本项目可借鉴：装饰外观与焦点环分离；数据颜色和节点尺寸保留语义。当前无需把所有节点替换成外部图片。

### Obsidian：圆节点与连线可读性优先

官方将节点明确描述为圆形，链接越多节点越大；分组按查询赋色，悬停突出关联，提供标签透明阈值、节点大小和连线粗细控制。官方帮助没有公开恒星光晕算法，也没有足够证据说明其内部渲染技术。[官方 Graph view 文档](https://obsidian.md/help/plugins/graph)

本项目可借鉴：星体外观不能牺牲分组颜色、点击目标和聚焦关联。不能把 Obsidian 当作已验证的发光星体实现案例。

### InfraNodus：暗色主题与标签层级

官方支持亮暗背景、不同调色板、按节点大小设标签阈值、固定或比例字号、直线或曲线边。该帮助页于 2021 年更新，节点数量建议具有历史性，不应当作现代性能上限。公开仓库声明使用 Sigma.js，但也明确它是最后更新于 2020 年的旧版，不能据此断言现行 SaaS 的引擎或着色器。[官方外观设置](https://support.noduslabs.com/hc/en-us/articles/360018669439-How-to-Change-the-Appearance-and-the-Settings-for-Your-Graphs)、[官方旧版仓库与版本声明](https://github.com/noduslabs/infranodus)

本项目可借鉴：暗色背景、节点颜色与标签层级共同工作，比单独加光晕更重要。没有公开证据支持“现行 InfraNodus 通过某种 shader 绘制星体”的说法。

### Nomic Atlas / Deepscatter：大量数据点的性能路线

Nomic 官方 Deepscatter README 声明其为 Atlas 的底层绘图引擎，公开了按缩放需要加载 Arrow 四叉树数据、REGL 管理 WebGL 缓冲、GPU 执行视觉映射的路线。该声明能证明公开引擎的机制，不能证明现行 Atlas 的所有界面仍完全相同，也不能证明其点具有物理星光外观。[官方仓库](https://github.com/nomic-ai/deepscatter)

本项目可借鉴：如果以后数据规模迫使改引擎，应围绕批量绘制和按需数据处理评估，而非只为光晕换 WebGL。当前只借鉴思路，不复用其代码或引入依赖。

## 当前代码与实施判断

当前 `src/map-canvas.ts` 的 `drawNode` 集中绘制节点，已存在种子光晕、重要节点呼吸光晕和选中环；`readTheme` 已识别暗色模式；`hit` 使用节点半径与输入容差判定命中。`src/graph-surface.ts` 和样式已有装饰星空背景。以上为当前工作区源代码证据，不是外部产品事实。

建议第一版只扩展暗色 `drawNode`：亮核 + 原数据颜色的受限光晕；光晕不扩张点击范围，不改布局半径；保持选中环清晰。普通节点保持静态，继续尊重减少动态效果。密集图中控制光晕半径和透明度，必要时缩放远景降低光晕。

验收应覆盖暗色普通/种子/重要/选中/淡化节点，浅色回归，密集区域标签与箭头辨识，以及拖动和缩放帧耗时。只有实测直接渐变绘制不够快，再考虑缓存精灵；不预先引入全局 bloom、3D 球体、全节点闪烁或新的图形库。

## 尚未验证

本次未逐一运行外部产品或测试其设备性能；未测量本项目改动后的帧耗时，未复制外部源码或资源。所有迁移建议都是基于公开机制与本地 Canvas2D 架构的工程判断。

## 第一版实施（2026-10-28）

用户确认执行后，已在 [map-canvas](../src/map-canvas.ts) 接入暗色同色窄光晕、保留数据色实体核和局部提亮。普通节点外晕最多 3 CSS px，重要节点为 4–7 px 并复用原呼吸，种子为 10 px；小半径按比例减少外晕。种子标记与选中环分别绘制，暗色悬停有细环。核与光晕共用原焦点淡化透明度。浅色普通节点仍为原实体圆；节点布局、数据半径及命中判定未修改，无新依赖或普通节点动画。

[浏览器回归](../scripts/verify-review-browser.ts)新增暗色三层共同淡化、实体数据色、悬停细环、种子双环及浅色原样断言，已通过完整回归。TypeScript、ESLint、离线 UI/unit、UI 合同和生产构建通过；已打开实际暗色预览检查。另加入 300 节点连续视图更新的绘制耗时记录，输出在回归页 `data-star-render-ms`；它只测同步 Canvas 提交耗时，不代表 GPU 完成时间或真实宿主交互帧率。真实 Obsidian 密集图拖动/缩放及改动前后性能对比仍待验证，暂不据此引入缓存。

本机可见浏览器的完整回归最终通过；300 节点、483 条边、30 次连续平移与缩放更新，同步绘制中位数约 1.3 ms、P95 约 1.7 ms。另一次连续同步调用测得 1.1/1.8 ms，均非硬件通用性能保证。已查看普通样本及 300 节点暗色截图，数据颜色保留，密集图连线重叠仍沿用原关系布局；本轮没有调整边布局或标签避让。

## 外观修正：消除珠状圆盘

用户反馈第一版仍像旧圆点加白色光晕，未达到星体外观。暗色绘制因此改为两层点光源：同色低亮外晕，以及中心集中发亮、经过原数据色向边缘透明衰减的星核。去掉实心圆盘及其大面积白色覆盖；原数据半径定义渐变范围，命中范围与交互环不变。浅色仍保留原实心圆。新增真实 Canvas 像素断言，检查中心比周围明亮、色层保留原蓝色分量、原圆盘边缘透明度明显降低，防止回退成珠状节点。上一节性能数字对应修正前版本，不能沿用为此次测量。

## 后续外观迭代：亮核尺度与关系留白

用户继续授权外观改进后，亮核尺度按屏幕半径约束，增加从近白亮点到原数据色的过渡，避免大节点出现大白心、小节点没有明确亮核。暗色关系线在星核外收住，极近节点限制两端缩短总量，避免反向线段；暗色箭头按实际屏幕节点半径留出间距，修复缩放后箭头间距错误。浅色关系绘制保持原样。

完整浏览器回归通过，包括 0.5/3 倍缩放下箭头间距及星核留白断言。TypeScript、Lint、生产和预览构建通过。已用相同 45 节点样本实际渲染原配色/社群/年份三栏并查看截图，色层仍可区分，无需新增纹理或动画。300 节点/483 边连续视图更新同步提交中位数约 1.9 ms、P95 约 2.3 ms；本次使用平面视图，不能与早先年份布局数字推导性能提升。真实 Obsidian、GPU 完成耗时与完整视觉矩阵仍未验收。

## 恒星色调与局部动态细节

用户进一步授权增加细节、动画及更接近恒星的颜色。本轮重新核对以下一手资料：

- [CSIRO / ATNF：The Colour of Stars](https://www.atnf.csiro.au/resources/education/senior-astrophysics/photometry/colour/)：恒星是遥远点光源，颜色主要随有效温度从橙红、黄白过渡到蓝白；可见色来自不同波长的组合，不能直接把光谱峰值等同于显示色。该页还明确说明，照片中的星芒属于望远镜光学衍射，某些光晕属于成像过程的伪像，不能当作恒星表面的实体结构。
- [Stellarium StelSkyDrawer 24.x](https://stellarium.org/doc/24.0/classStelSkyDrawer.html)：分别提供点光源颜色、闪烁强度及开关、亮星外晕开关和星芒开关。这里借鉴各层分别控制的绘制方式，不复制天文星等模型。
- [Google 100,000 Stars 作者技术说明](https://web.dev/case-studies/100000stars)：远星使用粒子及色指数查色，近处太阳才加入表面纹理、日冕贴片及耀斑着色器。它是历史实现参考，不是本项目的性能基准；其近景太阳细节不适合直接铺到所有小论文节点。

实施采用艺术化的暖冷内核：按原色红蓝分量决定靠近暖白/橙色还是蓝白，内层再与原色混合，外围继续使用原数据色。没有给论文赋予物理温度，也没有把绿、紫社群统一变白；绿紫仍依靠外围色层区分。大小、配色模式、布局、命中范围及选中环不变。

种子与现有重要节点增加两轴细星芒，种子外晕与星芒长度缓慢起伏，暗色沿用约 7.8 秒的错相呼吸；普通节点静态。星芒是观测外观的艺术化处理，不模拟恒星结构。所有层仍受关联淡化影响；现有暂停按钮现在同时停止节点动画，减少动态效果固定几何并阻止动画循环，销毁时解除监听。浅色种子不新增动画循环。

浏览器检查覆盖暖冷色序、绿紫区分、星芒随时间变化、减少动态时固定、暂停/恢复循环以及既有环/边界断言；45 节点三种配色已实际渲染查看。最终完整回归通过，300 节点、483 边连续视图更新同步提交约 1.8 ms 中位数 / 2.0 ms P95，测量不代表动画完整帧率或 GPU 完成耗时。TypeScript、ESLint、离线 UI/unit、预览及生产构建通过。仍未进行真实 Obsidian 密集图性能验收；没有新增图片、依赖或替换图形引擎。

## 全节点 twinkle、星芒分级与缩放修正

本节替代上一版的暂停按钮及普通节点静态约定。用户要求持续动效后，主面板和 embed 共用的背景暂停按钮、监听及样式已移除；系统减少动态效果仍控制背景 CSS 与节点 Canvas 动画，运行时切换也生效。

暗色所有论文节点以约 11.7 秒周期在 68%–100% 亮度间缓慢变化，沿用呼吸工具并增强 ID 相位散列，避免相邻编号同步闪烁。种子和重要节点继续叠加约 7.8 秒外晕呼吸。聚焦淡化与 twinkle 相乘，交互环不随亮度起伏。紫色数据节点的内核现在向星云紫靠近，外围数据色仍保留；这是用户选择的艺术化色彩，不是物理恒星温度。

沿用现有重要性判定与归一化分数：普通节点无星芒，重要节点为 4 尖，分数达到 0.7 时为 8 尖，长度与线宽随分数增长；种子使用最高层级并保留种子环。未增加新数据判定规则。

缩放问题在共享预览中读到当前比例恰为 8.000，与原共享硬上限 8 一致；另发现连续滚轮/按钮事件从当前插值帧重算目标，导致尚未完成的缩放输入被覆盖。共享上限提高至 32，连续事件改为基于待完成目标累积，并使用该目标的坐标保持指针锚点。滚轮、按钮、触摸捏合与视图恢复共用上限。浏览器回归验证从 8 连续三次 1.2 倍输入达到约 13.824，离线验证覆盖 16、32 倍恢复及超限约束；实际主面板按钮也已越过 8 倍。

完整浏览器检查覆盖普通节点亮度随时间变化、减少动态固定、星芒数量/线宽分级与连续缩放。60 节点样本已实际渲染查看；另通过浏览器真实媒体模拟确认减少动态时节点循环停止、背景 animation 为 none，恢复系统设置后节点循环重启。最终回归的 300 节点同步提交约 1.8 ms 中位数 / 2.2 ms P95，仅供本机回归参考，不等于持续动画帧率。真实宿主和低性能设备的持续动画耗电仍未测量。

## 默认社群色协调

暗色第一组社群色由淡红换为蓝紫 `#969be8`，节点与图例共用主题变量；浅色继续使用原淡红，其余社群、年份等配色不变。浏览器回归验证暗浅切换时节点与图例均正确恢复，类型检查、Lint 和构建通过。尺寸沿用既有年份归一化被引量的平方根映射，半径为 4–14 CSS px，种子最小约 11 px；没有将装饰光晕范围当成数据尺寸。

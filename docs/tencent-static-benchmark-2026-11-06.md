# 腾讯北京静态前端对照测速

2026-11-06，Asia/Shanghai。原线上 https://graph.jieyu.ai/ 未切换，正式域名与API部署未改变。

## 方法

腾讯北京（ap-beijing-6）与美国现有VPS各启动一个相同的临时Caddy静态服务，仅监听回环18203端口，禁止外部API查询。使用当前正式Web构建3e19a871b4f59f95的同一套HTML/JS/CSS。通过本机SSH转发到4211、4212访问；临时服务设置30分钟自动过期，测试结束后主动停止。

两份镜像使用同样的HTTP、gzip、静态资源1小时缓存及HTML不缓存策略。浏览器测量时两边都加入同一段仅在DOM属性记录Navigation/ResourceTiming的探针，使用fixture样例，未查询真实文献或扣除生产额度。

27次HTTP请求均为200。公网入口单次HTML波动约1.88—6.28秒；美国私有通道首个样本10.42秒，后两个2.24和2.56秒，存在明显抖动。

美国再次访问的HTML首字节等待5.637秒，脚本就绪后到挂载只增加约35毫秒；因此该样本的主要瓶颈是页面响应链路，而不是图谱渲染CPU。

## 结论与边界

在当前电脑和网络下，北京线路显著更好，支持优先采用“北京静态前端、现有VPS文献与额度后台”的方向。未测公开腾讯域名、TLS握手、备案接入及API跨境反代，不能把私有HTTP的0.30秒直接承诺为正式网站首开速度。浏览器数字是单次对照而非总体统计；不包括真实文献建图与上游API耗时。
